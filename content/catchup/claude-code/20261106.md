## 今回の注目ポイント

- **複数のセキュリティ修正**。Bash の権限チェックをすり抜けられる脆弱性（細工した環境変数プレフィックスでコマンドの一部を権限チェックから隠す）、accept-edits / auto mode で `sed` が権限チェックをスキップする問題、worktree 作成時のサンドボックス脱出、`/rewind` がディレクトリ symlink 経由でファイルを復元 / 削除できる問題などをまとめて修正。
- **`permissions.denyInsteadOfPrompting` 設定を追加**。権限プロンプトで待たされるツール呼び出しを「拒否してターンを継続」できるようになった（ターミナルセッション・サブエージェント・チームメイトで有効）。無人運用でプロンプトに詰まらせたくない場合に使える。
- **auto mode の挙動を広範に変更**。テレメトリ / feature flag がオフの環境や LLM ゲートウェイ越しでは、サーバが確認できない呼び出しは「確認 or 拒否」となり組み込み分類器へのフォールバックがなくなった。`CLAUDE_CODE_AUTO_MODE_SERVER=0` で従来の分類器を使い続けられる（Bedrock / Vertex / Foundry は変更なし）。
- **MCP タスクがターミナルで動作するように**。MCP サーバがツール呼び出しをタスクとして実行すると即バックグラウンドへ移し、完了時に結果を Claude に伝える。`CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND`（即バックグラウンド化を止める）・`CLAUDE_CODE_DISABLE_MCP_TASKS`（機能自体を無効化）を追加。
- **設定ファイルの堅牢化を継続**。ディスク満杯時の `~/.claude.json` / 設定 / 編集ファイルの空化・切り詰めを修正。レガシー名の設定ファイルが現行設定を隠す問題を stderr で警告。Windows では別プロセスが開いているファイルをより長く待つよう改善。
- **`CLAUDE_CODE_DISABLE_FEATURE_FLAGS` を追加**。テレメトリを切らずに feature flag 取得だけを止められる（各フラグは組み込み既定値になる）。

## 新機能・変更（changelog）

> 対象バージョン: v2.1.319（既存ファイルは v2.1.318 まで収録済み）

### v2.1.319（2026-11-06）

**セキュリティ修正**
- Bash の権限バイパスを修正（細工した環境変数プレフィックスでコマンドの一部を権限チェックから隠せた）。
- accept-edits / auto mode で `sed` コマンドが権限チェックをスキップできた問題を修正。
- worktree 作成時のサンドボックス脱出を修正。
- `/rewind` がディレクトリ symlink 経由でファイルを復元 / 削除できた問題を修正。
- クオートされた語を含むコマンドを Bash の deny / ask ルールが取りこぼす問題を修正。セッションの厳密な Bash / PowerShell ask ルールが、より広い deny ルールに覆われる場合に「確認」ではなく「拒否」されるよう変更。
- self-hosted runner で `--trust-workspace false` がリポジトリの設定ファイル内フックやスキルの実行も止めるよう修正。

**権限 / auto mode**
- `permissions.denyInsteadOfPrompting` 設定を追加。権限プロンプトで待つツール呼び出しを拒否してターンを継続（ターミナル・サブエージェント・チームメイト）。
- auto mode: テレメトリ / feature flag オフ（LLM ゲートウェイ越し含む）ではサーバが確認できない呼び出しを確認 or 拒否し、組み込み分類器へフォールバックしない。`CLAUDE_CODE_AUTO_MODE_SERVER=0` で分類器を維持（Bedrock / Vertex / Foundry は不変）。
- LLM ゲートウェイ越しの auto mode: `CLAUDE_CODE_AUTO_MODE_SERVER=1` は `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` 設定時でもサーバ側チェックを有効化（managed settings で後者を設定するなら前者の `1` も必要）。プロジェクト設定やプラグインが一度オフにしたサーバ側チェックを再度オンにできないよう変更。managed settings の `CLAUDE_CODE_AUTO_MODE_SERVER=1` がゲートウェイ URL をそこだけで設定しサーバ管理設定を取得できないときに無視される問題を修正。
- `claude -p` が、安全チェック不在でアクションが拒否されたのに auto mode で 0 終了していた問題を修正（text / JSON 出力は 1 で終了）。
- 権限ルールや `autoMode` 設定が非常に大きいときに理由を言わず拒否する問題を修正（理由を説明し、`autoMode` deny ルール未設定ならターミナルで確認）。
- クライアントがモデル変更と auto mode 要求を連続送信したときに誤拒否される問題を修正。
- `/status` がサーバ側レビュー未到達（LLM ゲートウェイが落とす等）でも「Auto mode server: Enabled」と表示する問題を修正。

**MCP / タスク**
- ターミナルでの MCP タスクに対応（タスク実行を即バックグラウンド化し完了時に結果を通知）。`CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND`（即バックグラウンド化を止めツール呼び出し内で待機）を追加。feature flag 取得なしでも MCP タスクが動作するよう変更（Bedrock / Vertex / Foundry / LLM ゲートウェイ / `DISABLE_TELEMETRY`）。`CLAUDE_CODE_DISABLE_MCP_TASKS=1` で無効化。
- 旧ハンドシェイクの MCP サーバが接続失敗 / 空結果を返す問題（新サーバ向けの拡張を宣言していたため）を修正。
- claude.ai コネクタ上の長時間 MCP ツール呼び出しが `--resume` 後に結果を報告しないことがある問題を修正。

**環境変数 / 設定ファイル**
- `CLAUDE_CODE_DISABLE_FEATURE_FLAGS` を追加（テレメトリを切らず feature flag 取得のみ停止、各フラグは既定値）。
- `CLAUDE_CODE_PROXY_RESOLVES_HOSTS` を設定ファイルからは設定できないよう変更（ホストがネットワークを管理する環境ではプロセス環境で設定）。
- 設定ファイル書き込み直後（数秒以内）の編集が無視される問題を修正。
- レガシー名に残った設定ファイルが現行設定を警告なく隠す問題を修正（home に設定ファイルが 2 つあること・使用中のものを stderr に表示）。
- 読み取り専用フォルダ / bind-mount ファイルへの保存中にディスクが満杯になると `~/.claude.json` / 設定 / 編集ファイルが空 or 切り詰めになる問題を修正（1 セッションずつ保存）。
- Windows: 別プログラムが開いているファイルをより長く待つよう改善（保存中の kill で `~/.claude.json` が空になりにくい）。

**CLI / スラッシュコマンド / 診断**
- `/claude-api latency-optimize` を追加（Claude API コードで待たされる箇所を見つけ、より速い設定を eval で検証）。
- `/tasks` に「Earlier in this session」行を追加（終了済みサブエージェントを再オープンして再度メッセージ可能）。
- 先頭の空白 / タブ / 改行の後に打ったスラッシュコマンドが実行されずプレーンテキスト送信される問題を修正。
- `/context` が毎ターン視覚グリッド全体を Claude に送る問題を修正（表だけを読む）。ターミナルで表を短く保つよう各リストは最大 10 行、オンデマンド MCP ツールはサーバごとに 1 行共有。
- git リポジトリ最上位に `HEAD` という名のファイル / フォルダがあると diff が「Diff unavailable」になる問題、64 ターン以上がファイル編集したセッションで `/diff` ペインが空になる問題を修正。
- `/model` ピッカーで古いモデルを「More models」行にまとめるよう改善。誤記モデル名（`opus-5-5` 等）に対し更新を促すのではなく意図したモデルを提案するよう修正。
- `/rewind` が `/branch` 前のチェックポイントへコード復元時に「No files were restored」で失敗する問題、plan mode で中断したターンを別権限モードで再開時に再実行する問題を修正。

**Claude apps gateway**
- 支払い上限のない開発者の `/usage` に当日・今週・今月の支出を追加（ゲートウェイが本バージョン以降）。
- `admin.pooled_conflict_rule` / `admin.pooled_priority_order` を追加（複数グループに属する開発者のプール予算の支払い順）。
- 任意の `login_notice` 設定を追加（ブラウザ検証ページとサインイン画面に運用者定義メッセージを表示）。
- `CLAUDE_GATEWAY_LOG_FORMAT=json` を追加（運用ログを `severity` / `time` / `message` の JSON 行に）。
- 起動時警告を各種追加（別ポリシーの `availableModels` が名前指定のカスタムモデル ID を許す場合、`desktopHome` 未設定で `coworkTabEnabled: false` / `chatSessionRetentionDays` に依存するポリシー〔Claude Desktop の 11/10 変更に先立つ〕、AWS GovCloud と他 upstream の混在、環境内の base URL 変数、managed settings がヘッダで Bedrock ガードレールを指すが `bedrock` upstream に `guardrail` がない場合）。
- 上限エラー文言を改善（「spend limit reached · resets Dec 1」＋ `admin.blocked_message`）。upstream 呼び出し失敗警告が provider ではなく upstream 名を示すよう改善。全 upstream が Bedrock のとき Claude Desktop が常に失敗する web search ツールを出す問題を修正。

**課金 / サインイン警告**
- claude.ai ログイン終了後に `ant auth login` のサインインで継続すると Claude Console 組織に課金される旨を警告・起動時に請求先組織名を表示。
- Claude apps gateway のサインイン失効後も端末がテレメトリ / managed-settings 要求を送り `invalid_token` としてログされる問題を修正。

**サブエージェント / セーフガード**
- サブエージェントのハンドバック報告を verbose 外で展開すると内部マーカーと provenance 注記が出る問題を修正。
- セーフガードがサブエージェントを止めた後、Claude には「自分で作業する」のではなく「より狭いプロンプトで再試行 or ユーザーに伝える」よう指示するよう変更。
- バックグラウンドエージェントの後続報告が黙って失われる問題を修正（拒否された旨と要求方法を通知）。コンパクション後にサブエージェントが起動も引き継ぎもしていないバックグラウンドエージェントの完了通知を期待させられる問題を修正。

**cloud sessions / self-hosted runner / Remote Control**
- cloud sessions がワーカー移動時にセッションスコープの deny / ask 権限ルール（PermissionRequest フックが追加したもの等）を失う問題を修正。deny / ask を全て維持できないとき allow ルールを破棄するよう変更（再度確認される場合あり）。
- `/permissions` が cloud sessions で「利用不可」としか答えない問題を修正（ルールの場所と変更方法を表示）。
- cloud sessions: scheduled task が `memory` という名のコネクタを黙って落とす問題、「Send now」が待機メッセージでバックグラウンドエージェントを終了させる問題を修正。
- self-hosted runner: `CLAUDE_RUNNER_CHECKOUT_PATH` で各リポジトリに独自フォルダ（重複名は `-2`, `-3` …）。セッション終了時のデバッグログアップロードを廃止（失敗セッションのログは `--remove-session-state` なしならランナーホストに残る）。`--use-anthropic-git-proxy` / `--configure-git` で起動チェック失敗前に登録される問題を修正。
- `claude remote-control` が初回質問に無回答のとき status 0 で黙って終了する問題（理由を表示し 1 で終了）、改行なしの `y` を無視する問題を修正。

**VS Code**
- 5 万文字超のプロンプトが黙って切られる問題を修正（チャット欄に残して通知、超過ペーストは拒否）。plan mode で中断したステップがウィンドウリロード後に未承認プランを実行する問題を修正。
- 削除セッションのファイルが拡張でのリネーム後に復活する問題、Web タブ由来 cloud session が `/clear` / Retry / Edit で消したターンを戻す問題、巨大ワークスペースでのチャットパネル凍結や数式フェンスでの速度低下などを修正。

**Claude in Chrome**
- 接続がアクション途中で切れたとき拡張を「未接続」と報告する問題を修正（繰り返す前にページを確認）。切断後 6 秒まで自前ブラウザの復帰を待つよう改善。`javascript_tool` の結果が 6 万文字まで会話に残るよう改善（ファイル保存しない）。
- 拡張に保存されたショートカットを扱う組み込みツール `shortcuts_list` / `shortcuts_execute` を削除。

**その他の修正 / 改善**
- Linux の NFS / SMB / Lustre 等ネットワークファイルシステム上のプロジェクトで起動時に全ファイルを列挙する問題を修正。
- 読み取り専用コマンドを単純な `timeout DURATION`（例 `timeout 30 rg foo`）で包んだときの不要な権限プロンプトを修正。
- `which` にフラグを付けた実行（lookup / display 用途外）に権限確認を求めるよう変更。
- `--add-dir` ディレクトリは信頼ダイアログ承認後にのみプラグインマーケットプレイスを登録。サンドボックス ON 時、開始フォルダ以下の `.claude/skills` スキルはそこで起動 / `/cd` した場合のみロード。
- self-paced `/loop` はフォールバック起床をスケジュールせずターン終了時に終了するよう変更（`CLAUDE_CODE_LOOP_KEEPALIVE=1` で旧挙動）。cloud session で起床タイマーはコンテナ停止で止まる旨を注記。
- PostToolUse フックを、新メッセージがターンを中断した後に完了するツール呼び出しでも（最大 10 秒）実行するよう変更。
- Monitor の WebSocket watch が各 Bash コマンドでルールに従うよう変更（deny は拒否、ask 下では allow / bypass / auto mode でもプロンプトをスキップしない）。プロキシ越しで `CLAUDE_CODE_PROXY_RESOLVES_HOSTS` 設定かつ自前 DNS なしの環境で失敗する問題を修正。
- TLS 検査プロキシ越しの証明書自動修復を `ALL_PROXY` のみ設定時は実行しないよう変更（`HTTPS_PROXY` に http:// URL を設定）。`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` 設定時に証明書エラーが残る問題を修正。
- プラグイン: `claude plugin update` / `/plugin` の「Update now」が新バージョンの依存を入れない問題、`subagentStatusLine` で `${CLAUDE_PLUGIN_ROOT}` が展開されない問題を修正。
- Artifact データベース: DB なしアーティファクトへの呼び出しの扱い、`out_dir` 保存の拒否、存在しないドキュメント更新時のエラー文言などを修正・改善。
- 補足: Enterprise 向け Claude Tag、Code Review（GitHub 組織リンク解除時の All repositories 無効化）、各種アクセシビリティ・コントラスト改善など多数。

## 使い方メモ（任意）

- 無人運用で権限プロンプトに詰まらせたくない場合、`permissions.denyInsteadOfPrompting` を使うと「待つ代わりに拒否してターン継続」にできる（ターミナル / サブエージェント / チームメイト）。
- テレメトリや feature flag を切っている環境では auto mode のサーバ側チェックが必須になった。従来の組み込み分類器を使い続けたい場合は `CLAUDE_CODE_AUTO_MODE_SERVER=0` を設定する（Bedrock / Vertex / Foundry は影響なし）。
- セキュリティ修正（Bash 権限バイパス・`sed` の権限スキップ・worktree サンドボックス脱出・`/rewind` の symlink 経由操作）を含むため、auto mode / accept-edits やサンドボックスに依存している運用は v2.1.319 への更新が推奨。
