## 今回の注目ポイント

前回（2026-09-19 収録、v2.1.278 まで）以降、changelog に **v2.1.279**（リリースノートなし）と **v2.1.280**（2026-09-22 更新）が追加された。今回の目玉は **新モデル Claude Opus 5.5（`claude-opus-5-5`）の追加**で、これが新しい既定 Opus モデルになった（1M コンテキスト、$4/$20 per Mtok、キャッシュ読み取り $0.20/Mtok）。あわせて **Pro / Team Standard プランの既定モデルが Sonnet から Opus に変更**され、Max・Team Premium・Enterprise と揃った。さらに、シンボリックリンク経由の書き込みに対する権限判定の安全性強化、auto モードのリトライ挙動の修正、`CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH` の追加、多数の UI/UX 修正、VSCode 拡張・Web・Slack（Claude Tag）向けの機能追加が含まれる大型リリース。

## 新機能・変更（changelog）

> 対象バージョン: v2.1.279 〜 v2.1.280

### v2.1.280（2026-09-22）
- **バージョン**: v2.1.280（2026-09-22）
- **内容**:
  - **モデル / 既定モデル**:
    - **Claude Opus 5.5（`claude-opus-5-5`）を追加し、新しい既定 Opus モデルに**。1M コンテキスト、$4/$20 per Mtok、キャッシュ読み取り $0.20/Mtok。
    - **Pro / Team Standard プランの既定モデルを Sonnet → Opus に変更**（Max・Team Premium・Enterprise と統一）。
    - `/effort` が「モデル単位」になる前に保存された effort レベルは、Opus 5.5 など新規リリースモデルには適用されず、レベルを選ぶまで各モデルの既定で開始するよう変更。
    - Opus 4.7 / Opus 4.8 / Fable 5 は、`-p`・Agent SDK・プロジェクト/管理/`--settings` の `effortLevel`・モデル単位レベルにおいて、launch-default の effort を保持しないよう変更。
  - **MCP**:
    - **`CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH` を追加**。MCP ツールの説明・サーバー指示に対する 2,048 文字上限をセッション内の全 MCP サーバーで変更できる。
    - `claude mcp remove` 後に同名で再追加した MCP サーバーが、再接続せず「要認証」表示のままになる不具合を修正。
    - `/mcp` の一覧では △、詳細では ⚠ と表示が食い違っていたのを、一覧・詳細・`/plugin` すべて ⚠ に統一。
  - **権限・auto モード・安全性**:
    - シンボリックリンク経由の書き込みが in-tree の綴りで判定されていた問題を修正。プロンプトが実際の書き込み先を明示し、`acceptEdits`・allow ルール・auto モードがツリー外への書き込みを誤って許可しなくなった。
    - 安全性チェックがレビューを拒否した際に auto モードが同じアクションを無限リトライする問題を修正（一度だけ拒否し、リトライは無意味と通知）。
    - 安全性チェックが無回答のとき auto モードが停止なく拒否を繰り返す問題を修正（バックオフし、連続10回でメッセージを出してターン停止）。
    - `PermissionRequest` フックで agent タイプのフックが実行されなくなった（回答が許可/拒否に結びつかないため）。command / http フックを案内するエラー表示に変更。
    - `/permissions` の改善: ルール閲覧・追加・削除後にルール一覧へフォーカスが戻り、削除・ディレクトリ削除の確認は既定 No に。←/→・Tab でのタブ切替がフォーカスをタブバーに移さないよう改善。
  - **ツール・ホスト連携**:
    - Write 呼び出しで `file_path`/`content` の代わりに `path`・`file_text`・`file_content` や余分な `description` を送ってもバリデーション失敗しないよう修正。
    - ホストアプリ（Claude Desktop・VS Code・SDK）から作業中にモデル切替した際、次プロンプトでプロンプトキャッシュミスになる問題を修正。
    - resume した fork サブエージェントがツール一覧を再構築してキャッシュを壊す問題、サブエージェントの hand-back メッセージが verbose 外で内部 provenance を表示する問題などを修正。
    - バックグラウンドセッション（`claude --bg`）・サブエージェント関連の多数の修正（メッセージ喪失、LSP ツール利用不可、Ctrl+C 応答など）。
  - **Artifact**:
    - 組織ポリシーが読めない場合に Artifact ツールが黙って消えていたのを、原因を表示するよう改善。
    - Artifact のリンクを読めないときにユーザーへ通知してから続行するよう改善。
    - artifact republish 時にストレージ DB アクセスルールがリセット/ビューアプロファイルスコープが欠落する問題を修正（欠落した再送は拒否）。
    - artifact ページの改善（Print ボタン非表示、ダークモードのフォーム/スクロールバー対応、email/phone をテキスト表示 等）。
  - **UI/UX（ターミナル）**:
    - フルスクリーンでより多くの一覧にマウス対応（`/skills` 一覧のホイールスクロール、`/plugin` のスキル状態オプションのクリック）。
    - ほとんどのダイアログで Ctrl+C / Ctrl+D 二度押しが Claude Code を終了させていた問題を修正（ダイアログを閉じるだけに）。
    - `n`/`y` が誤ってダイアログを閉じる/確定する問題を修正（Enter/Esc で確定/取消。`keybindings.json` で復元可）。
    - `ctrl+l` / `cmd+k` のフルスクリーン transcript クリア（2.1.260 で追加）を revert し、画面再描画に戻した。
    - 音声ディクテーションの Ctrl+C / Esc / Space 関連の修正、Windows での不可視文字処理後のプロンプト行乱れの修正 など多数。
  - **その他プラットフォーム**:
    - **[VSCode]** Status ダイアログ（`/status`）、Sandbox ダイアログ（`/sandbox`）、Claude in Chrome ダイアログ（`/chrome`）、Export conversation（`/export`）、Slash commands にスキル情報を追加（`/skills`）、`/plan` を追加。貼り付けテキストの扱い改善（800文字/2改行超をマーク、不可視 Unicode 除去）。
    - **[Claude Code on the web]** 管理者の Routines 設定が Admin settings → Capabilities → Remote sessions 配下に移動。GitHub Enterprise Server での token 自動更新、routine セッション編集の修正 等。
    - **[Claude Tag（Slack）]** Slack ネイティブの Working インジケータ・Stop ボタン・スレッドタイトルに対応。ゲスト参加/退出時の通知、スケジュール routine の修正、ファイルスキャンのリトライ、箇条書きレンダリング修正 等。
    - **[Code Review]** REVIEW.md の指示がサイズ上限で省略された際に、ファイル名と上限を明示するよう改善。

## 使い方メモ（任意）

- **Opus 5.5 利用者**: v2.1.280 以降、既定の Opus が Opus 5.5（1M コンテキスト）になる。`/effort` がモデル単位化する前に保存した effort レベルは新モデルには引き継がれないため、Opus 5.5 では改めて effort レベルを選ぶ必要がある。
- **Pro / Team Standard 利用者**: 既定モデルが Sonnet から Opus に変わったため、コストや速度を重視する場合は `/model` で明示的に切り替えるとよい。
- **MCP ヘビーユーザー**: ツール説明が 2,048 文字上限で切られて困る場合は `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH` で上限を変更できる。
- **シンボリックリンクを含むワークツリー**: 書き込み先がツリー外のシンボリックリンク経由でも正しく判定されるようになったため、`acceptEdits`/auto モード利用時の想定外の書き込み許可が防止される。
