## 今回の注目ポイント

- **v2.1.304 の1リリースを収録**（前回収録は v2.1.303 / 2026-10-18）。多数の修正・改善に加え、いくつかの新機能が追加された。
- **`/auto-mode-setup` を追加**: プロジェクトと直近セッションを読み取って auto モードに環境を学習させるガイド付きセットアップ。Bedrock / Vertex / Foundry / Claude アプリゲートウェイ / テレメトリ無効セッションでも利用可能に。
- **`/claude-api managed-agents-secure` を追加**: Managed Agents のエージェント設定を Anthropic 公開のセキュリティガイドと照合する（変更は加えない）。
- **Pro / Max プランで、長時間放置した会話を再開すると5時間利用上限の大きな割合を消費する場合に警告**を表示するようになった（そのまま再開するか、新規会話を開始して必要なら前の会話を参照させる）。
- **`rm -r` の安全プロンプトを強化**: マウントドライブやその直下フォルダ（`/Volumes`・`/media`・WSL の `/mnt/c`）の `rm -r` が `rm -rf /Applications` と同様の安全確認を受けるよう修正。
- **Code Review にレビューレベル（Quick / Standard / Deep）を追加**。組織単位の既定を選べ、リポジトリ個別に設定も可能。GitHub 組織内の全リポジトリ（後から追加されたものを含む）を一括レビュー対象にするオプションも追加。

## 新機能・変更（changelog）

> 対象バージョン: v2.1.304

### v2.1.304（2026-10-19）

- **リンク**: https://github.com/anthropics/claude-code/releases/tag/v2.1.304

- **新機能 / 追加（抜粋）**:
  - `/auto-mode-setup` を追加（プロジェクト・直近セッションを読み取り auto モードに環境を学習させるガイド付きセットアップ。Bedrock / Vertex / Foundry / Claude アプリゲートウェイ / テレメトリ無効セッションでも利用可能に）。
  - `/claude-api managed-agents-secure` を追加（Managed Agents のエージェント設定を Anthropic 公開のセキュリティガイドと照合。変更は加えない）。
  - Pro / Max プランで、非アクティブな会話の再開が5時間利用上限の無視できない割合を消費する場合の警告を追加。
  - mod の `tool.check` 応答に `decider: "person"` を追加（許可ダイアログかホストのコールバックのみが承認でき、誰にも尋ねられない場合は mod の理由で拒否）。`tool.check` イベントに読み取り専用呼び出しを示す `e.isReadOnly` を追加。
  - 先に実行されたプラグインがあなたの mod のフックをスキップした際、イベント名とプラグイン名を示すトランスクリプト行を追加。
  - トランスクリプトビュー（Ctrl+O）のコンパクション要約に、以前呼ばれたツール名を表示。

- **主な修正（抜粋）**:
  - 起動時に `ANTHROPIC_API_KEY` を承認、または `/config` で "Use custom API key" を切り替えた後、次の毎時チェックまで組織ポリシーが更新されない問題を修正。
  - Linux のサンドボックスコマンドが、`sandbox.filesystem.denyRead` のグロブに文字クラスでない角括弧（`[user-id]` のようなルートフォルダ）を含むと起動に失敗する問題を修正。
  - `rm -r` のマウントドライブ/トップレベルフォルダ（`/Volumes`・`/media`・WSL の `/mnt/c`）が `rm -rf /Applications` 相当の安全確認を受けない問題を修正。
  - `CLAUDE_CODE_TRANSCRIPT_LOCAL_GC` が、ファイルのトリム中にディスクが満杯になると保存済みトランスクリプトからメッセージを落とす問題を修正。
  - プラグインがサブエージェントの生成や完了済みエージェントの再実行で、`--max-turns`・Stop・入力終了後も headless 実行を続けさせる問題を修正。
  - mod のリロード失敗が、ロードされたまま残るバージョンのツール/コマンドを削除し、前バージョンがまだロード中かのメッセージが誤り/無言になる問題を修正。
  - LLM ゲートウェイ越しの `context_management: Extra inputs are not permitted` エラーを修正（当該フィールドを外して再送）。
  - SDK / デスクトップセッションで、モデル切替・メッセージ・中断がコンテキスト使用量チェックの後ろで待たされる問題を修正。
  - サブエージェントが、完了直後にメッセージ送信/再開されると直近の作業を忘れることがある問題を修正。
  - `claude --worktree` が HEAD デタッチ時/別ブランチ時に終了時 worktree とブランチを無確認で削除しコミットを失いかねない問題を修正。
  - スケジュールされた Cowork クラウドセッションが、WebFetch の URL 承認を誰も与えられないサブエージェントごとに5分待つ問題を修正。
  - 定期ルーティン用途に関わる複数のクラウドセッション/Remote Control/Claude Tag の修正（下記の各環境別セクション参照）。
  - `/effort status`・`/effort ultracode`・プロンプトの effort 表示が、`CLAUDE_CODE_EFFORT_LEVEL` が `auto`/未設定でレベル未送信のとき推測値を出す問題を修正。
  - `CLAUDE_CODE_AUTO_COMPACT_WINDOW=200k` が黙って 100K ウィンドウになる問題を修正（`k`・`M` サフィックスに対応し、範囲外/無視時に警告）。
  - エージェントチーム: メインセッションからのシャットダウン要求承認が CLI 全体を終了させなくなった。
  - `claude --help` の `--tools`・`--resume`・`--debug`・`--json-schema`・`--disable-slash-commands`・`--system-prompt-snapshot`・`claude update` の説明を実挙動に合わせて修正。

- **変更 / 改善（抜粋）**:
  - mod の `settings.read` フックが各設定レイヤーを受け取りマージ後設定を書き換えられるよう変更（管理 mod が組織設定を上限として扱える。保持スイープが使う `cleanupPeriodDays` を含む）。
  - `/artifacts` の削除確認を番号選択に変更（1 または Enter で保持、2 で削除。y/n/Esc も引き続き有効）。

## 使い方メモ（任意）

- **`/auto-mode-setup`**: auto モードを使う前に、プロジェクトと直近セッションから環境を学習させておけるガイド付きセットアップ。Bedrock / Vertex / Foundry / Claude アプリゲートウェイ / テレメトリ無効環境でも使えるようになった。
- **`/claude-api managed-agents-secure`**: Managed Agents のエージェント設定を Anthropic 公開のセキュリティガイドと照合して差分を確認できる（設定変更は行わない）。セキュリティ設定の点検に。
- **Pro / Max プランの利用上限警告**: 放置した会話の再開が5時間利用上限を大きく消費しそうなとき警告が出る。そのまま再開するか、新規会話を始めて必要時に前の会話を参照させる運用が選べる。
- **`rm -r` の安全確認強化**: マウントドライブやその直下（`/Volumes`・`/media`・WSL の `/mnt/c`）への `rm -r` でも安全プロンプトが出るようになったので、誤削除リスクが下がった。
