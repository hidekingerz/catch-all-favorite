## 新機能・変更（changelog）

> 対象バージョン: v2.1.271 〜 v2.1.273（新しい順）

### v2.1.273（2026-09-15）

**新機能・追加**
- **LLM ゲートウェイ向けリクエストヒントヘッダー**: `x-claude-code-request-class` / `x-claude-code-agent-type` / `x-claude-code-prev-tool-durations` / `x-claude-code-compaction` / `x-claude-code-context-compacted` を追加。`CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` でオプトイン。
- **MCP サーバ切断通知**: セッション中に MCP サーバが切断され自動再接続を諦めた際に通知し、`/mcp` を案内。
- **リモートコントロールセッションのフォーク**: `claude --remote-control` / `/remote-control` で開始したセッションを Claude アプリからフォーク可能に（フォークは自分の PC 上のバックグラウンドセッションとして動作）。

**主な変更**
- auto mode（Bedrock / Vertex / Foundry）を当面ローカル分類器を既定に変更。サーバ側分類器を使うには `CLAUDE_CODE_AUTO_MODE_SERVER=1`。
- `OTEL_LOG_TOOL_DETAILS=1` がコスト/トークンメトリクスに実際のエージェント・スキル・プラグイン・MCP サーバ名も含めるように。
- Claude アカウントでのサインイン時に claude.ai プラグインへのアクセスも要求するように。
- `/bug`・`/feedback` レポートを直近 API リクエストのモデル挙動パラメータ（model / system prompt / tools）のみに限定し、リクエストメタデータや `CLAUDE_CODE_EXTRA_BODY` を除外。
- 2.1.268 の変更（解析不能な Bash 行への Read/Edit deny ルール適用）を一部リバート。`time -p make build` のようなコマンドは拒否ではなく再度プロンプトへ。

**主な修正**
- 権限チェッカーが完全解析できない Bash コマンドが `permissions.blockReadsOutsideWorkingDirectories` 下でプロンプトをスキップする問題、bypass モードでサブシェルに隠れた危険な `rm` を修正。
- claude.ai から同期したスキルが組織で Skills を無効化した後も残る問題（復元可能なゴミ箱へ移動するように）を修正。
- MDM/`managed-settings.json` の `allowManagedMcpServersOnly` / `deniedMcpServers` / `disableClaudeAiConnectors` がサーバ管理設定併存時に無視される問題を修正。
- Bedrock/Vertex/Foundry の 401/403 や Claude アプリゲートウェイ 403 のメッセージが更新すべき資格情報を明示するように。
- コンテキストメーターと auto-compact がアドバイザーツールのターンを約2倍で計上し、実ウィンドウの半分で発火していた問題を修正。
- サブエージェント/バックグラウンドエージェントが、最終応答にトークン使用量やモデル ID が欠けると「失敗」扱いされ結果が届かない問題を修正。
- `/tui` が既に作業を終えたエージェントチームのメンバーのために再起動を拒否する問題、`.claude/scheduled_tasks.json` を別フォルダにコピーした際にタスクが誤ったセッションで実行される問題を修正。
- Artifact 関連: パブリッシュ接続断時の安全な再送（重複回避）、DB 更新で単一フィールドのみ削除可能に、など複数改善。
- [Code Review] `/ultrareview --post` の再試行時に findings コメントが二重/ゼロになる問題、大文字を含むリポジトリ名で空プッシュが再レビューされる問題を修正。
- [Claude Tag] 組織共有プライベート Slack チャンネルの scheduled task が無言で投稿されない問題、AWS のリージョンレスエンドポイント署名などを修正。

### v2.1.272（2026-09-15）
- 不具合修正・信頼性改善のみ（changelog 記載は "Bug fixes and reliability improvements"）。

### v2.1.271（2026-09-14）

**新機能・追加**
- **Remote セッションでの fast mode**: クラウド/セルフホストランナーの Remote セッションで、ホストの fast-mode 設定またはセッション内 `/fast` が組織の許可範囲で適用。
- **`/config` パネルのマウス操作**（フルスクリーン時）: ホイールでスクロール、値をクリックで変更、ポインタ下の行をハイライト。
- **`claude self-hosted-runner --drain-marker-file <path>`**: SIGTERM drain 時に該当ファイルがあればホスト drain として報告（テレメトリのみ）。
- **auto mode サンドボックスのコマンド単位 `allowed_domains`**: Bash/PowerShell/Monitor でコマンドが必要とするホストをそのコマンド専用に開放、他は拒否。
- **`omitClaudeMd`**: エージェント frontmatter と `--agents` JSON に追加。カスタム/プラグインのサブエージェントを user/project/local の CLAUDE.md 抜きで実行可能に（管理ポリシーファイルは引き続きロード）。
- **`--accept-command <sha256>`**: `claude plugin install`/`update` で、直前の `--json` 実行が表示したコマンドを `-y` の代わりに厳密に受理。
- **`modelPricing` の `multiplier`**（1超〜最大10）: 社内チャージバック用のマークアップ料率を管理設定/Claude アプリゲートウェイの `pricing` ブロックでサポート。

**主な変更**
- **Monitor watch のタイムアウト仕様変更**: 常にデッドライン付き（最大30分、`-p` 単発実行では10分）に。タイムアウト無しの `persistent` オプションを廃止し、Claude に再アームを通知。
- **動的ワークフローの既定サイズ縮小**: Pro プランで既定を small に、medium のガイドラインを15→10エージェントに。
- auto mode で、スキル/スラッシュコマンドのインライン `!` シェルコマンドが分類器ではなく default モードの権限ルールに従うように。
- auto mode でサブエージェントが専用のハンドバック呼び出し経由でセーフティ分類器のレビューを受けるように。
- IDE 選択インジケータを `[⧉ …]` のピル表示に変更（複数行プロンプトを圧迫しない）。
- Markdown ファイルを artifact としてパブリッシュするとスタイル付きドキュメントページ（タイトルヘッダー・タイポグラフィ・シンタックスハイライト）でレンダリング。
- artifact watch の同時監視上限を 5→10 に。

**主な修正（抜粋）**
- アカウント/組織/API キー切り替え後にキャッシュされた組織ポリシーが再利用される問題、起動後にポリシーロードが完了してもツール/コマンド一覧が更新されない問題を修正。
- MCP OAuth のクライアント登録の誤処理、MCP ツールをフル名でなくベア名で選んだ際にツール検索がマッチしない問題を修正。
- `--resume` 系: 1M コンテキストウィンドウ（`[1m]`）が失われる、`/artifacts` で添付した artifact が消える、前会話のファイル読取追跡を引き継ぎ未読ファイルを編集し得る問題などを修正。
- 動的ワークフローが usage limit で一時停止しリセット後に自動継続するよう改善。
- ターミナル描画性能・起動時間・フック進捗表示の改善。
- [VSCode] Attach Open File 設定を追加、Hooks/Permission ダイアログの保存不具合、Windows でのコンソールウィンドウ点滅など多数修正。
- [Claude Code on the web] Routines ページを Yours/Templates タブの新レイアウトに変更、Cloud environments 管理にカスタムネットワークアクセスを追加。

## 使い方メモ（任意）

- **`omitClaudeMd`** はサブエージェントに CLAUDE.md の文脈を持ち込みたくない場合に有効。カスタム/プラグインエージェントの frontmatter か `--agents` JSON で指定でき、管理ポリシーは維持される。
- **Monitor watch** は `persistent`（無期限）が廃止され最大30分のデッドライン制に変わったため、長時間の監視は再アーム前提の運用に見直すとよい。
- **auto mode + サンドボックス**で外部ホストへアクセスするコマンドを扱う場合、コマンド単位の `allowed_domains` を使うと必要なホストだけを最小権限で開放できる。
