## 今回の注目ポイント

旧 Developer ID 証明機関（Sub-CA）が **2027年2月1日に失効**し、同機関が発行した証明書はその日以降使えなくなる。Mac アプリや `.pkg` インストーラを配布している開発者は、対象証明書の有無を確認し、現行の認証局「Developer ID Certification Authority (G2)」で新しい証明書を再発行したうえで、失効日より前に再署名する対応が必要になる。特に `.pkg` は失効した証明書で署名されていると 2027年2月1日以降インストールできなくなるため、期限前の再署名が必須。

### Upcoming expiration of Developer ID Certification Authority (Sub-CA)
- **URL**: https://developer.apple.com/jp/news/?id=w4atic4c
- **公開日**: 2026-10-01
- **要約**: 旧 Developer ID Certification Authority（Sub-CA）が 2027年2月1日に失効し、同機関が発行した証明書は同日以降機能しなくなる。対応は3段階: (1) 影響確認 — [Certificates, Identifiers & Profiles](https://developer.apple.com/account/resources) で 2027年2月1日以前に失効する証明書を確認する。(2) 新証明書の作成 — 現行認証局 Developer ID Certification Authority (G2)（2031年まで有効、ただし発行される証明書は毎年更新が必要）で再発行する。Xcode 11.4 以前を使っている場合は先にアップデートし、中間証明書の選択時は「G2 Sub-CA」を選ぶ（別の選択肢だと再び2027年失効の証明書になる恐れがある）。(3) 配布形態に応じた再署名 — 影響を受ける証明書で署名した `.pkg` は 2027年2月1日以降インストール不可になるため期限前にすべて再署名する。セキュアタイムスタンプ付きで署名・公証済みの Mac アプリは引き続き動作し対応不要だが、今後の更新では新証明書で署名しノータライズ用にセキュアタイムスタンプを含める。
