## 今回の注目ポイント

Chrome 155 関連の 2 本の変更が公開された。1 つは Digital Credentials API の発行（issuance）機能が Chrome 155 でデフォルト有効になり、オリジントライアルのトークンやフラグなしでモバイルウォレットへの認証情報発行が可能になった件。もう 1 つは長年進めてきた `unload` イベントの非推奨化が Chrome 155 で完了し、Chromium 系ブラウザでデフォルトで `unload` ハンドラーが発火しなくなった件。いずれも Chrome 155 を使うプロジェクトに直接影響するため、依存コードの確認が必要。

## 記事一覧

### Digital Credentials API issuance ships in Chrome 155
- **URL**: https://developer.chrome.com/blog/digital-credentials-api-issuance?hl=ja
- **公開日**: 2026-10-23
- **要約**: Chrome 155 以降、Digital Credentials API の発行（issuance）機能がデフォルトで有効になり、オリジントライアルのトークンや `chrome://flags` の設定が不要になった。発行元サイトは `navigator.credentials.create()` に発行リクエストを渡し、ユーザーのモバイルウォレットアプリへ新しい認証情報（デジタル学生証など）を直接追加できる。オリジントライアル時からの変更点として、各呼び出しにユーザー操作が必須になった点、キャンセル時のエラーが `NetworkError` から `NotAllowedError` に変わった点、不透明なオリジンからの呼び出しがブロックされる点などがあり、既存コードの更新が必要になる場合がある。

### Unload event deprecated in Chrome
- **URL**: https://developer.chrome.com/blog/unload-deprecated-in-chrome?hl=ja
- **公開日**: 2026-10-16
- **要約**: Chrome 155 で `unload` イベントの非推奨化が完了し、Chromium 系ブラウザではデフォルトで `unload` ハンドラーが発火しなくなった。`unload` の利用はナビゲーションの約 18% から 4% 未満まで減少しており、これにより bfcache の利用機会も拡大している。記事は開発者に対して `unload` への依存をやめるよう促している。
