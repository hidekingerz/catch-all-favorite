# 4. 「キャッシュが効いている」は、通信していないという意味か

> 所要時間: 読むのに 8 分、手を動かして 3 分
> ゴール: サーバが付けたヘッダの値を見て、2 回目にブラウザが問い合わせないか、確認だけするか、毎回取り直すかを判定できる
> 前提: [1 章](01-quickstart.md)（リクエスト、レスポンス、ヘッダ）

## 0. 一枚で

ブラウザは、一度受け取ったレスポンスのコピーを手元に置き、次に同じものが必要になったときに使い回します。どう使い回すかは、サーバがレスポンスに付ける `Cache-Control` というヘッダで決まります。

| `Cache-Control` の値 | 2 回目にブラウザがすること | 会話での言い方 |
|---|---|---|
| `max-age=秒数` | 期限内は、サーバに問い合わせない | キャッシュが効いている |
| `no-cache` | 毎回サーバに確認する。変わっていなければ、手元のコピーを使う | 再検証している、304 が返っている |
| `no-store` | コピーを置かない。毎回、本体を取り直す | キャッシュしていない |

「キャッシュが効いている」には、通信が起きていない場合（1 行目）と、通信して確認だけしている場合（2 行目）があります。

## 1. 手元のコピーを使い回す

1 章で見たとおり、1 ページを開くには何往復もかかります。ところが、見た目の指定や画像は、ページを移っても同じものを使うことがよくあります。

そこでブラウザは、受け取ったレスポンスを手元に保存しておきます。この保存場所と仕組みを **HTTP キャッシュ** と呼びます。

困るのは、サーバ側のファイルが新しくなったときです。手元のコピーを使い続けると、古いものが表示されます。

どこまで使い回してよいかは、ファイルを持っているサーバにしか決められません。サーバはそれを、レスポンスのヘッダ `Cache-Control` に書いて伝えます。

## 2. 演習: 2 ページ目に何が起きるか

<!-- exercise: ex-second-visit -->

2 つのページがあり、どちらも同じ 3 つの CSS ファイルを使います。3 つの違いは、サーバが付ける `Cache-Control` の値だけです。

| ファイル | `Cache-Control` |
|---|---|
| `/long.css` | `max-age=3600`（3600 秒 = 1 時間） |
| `/check.css` | `no-cache` |
| `/never.css` | `no-store` |

1 ページ目を開いたときは、3 つともサーバに届き、サーバは本体を返します。

続けて 2 ページ目を開いたとき、3 つのファイルのリクエストは、それぞれサーバに届くでしょうか。0 節の表を見て予想してから、実行してください。

```sh
node examples/04-cache.mjs
```

<summary>答え</summary>

```

  /long.css   Cache-Control: max-age=3600  届いた → 200（本体を送った）
  /check.css  Cache-Control: no-cache      届いた → 200（本体を送った）
  /never.css  Cache-Control: no-store      届いた → 200（本体を送った）
2 ページ目を開いたとき
  /long.css   Cache-Control: max-age=3600  サーバに届いていない（手元のコピーを使った）
  /check.css  Cache-Control: no-cache      届いた → 304（変わっていない、と答えただけ。本体は送っていない）
  /never.css  Cache-Control: no-store      届いた → 200（本体を送った）
```

3 つとも、結果が違います。次の節で 1 つずつ読みます。

## 3. 3 つの結果を読む

### `max-age`: 問い合わせない

`/long.css` は、2 ページ目ではサーバに届いていません。ブラウザは「1 時間は使い回してよい」と言われたので、リクエストを送らずに手元のコピーを使いました。

3 つの中でいちばん速い結果です。往復が 1 回、まるごとなくなります。

代わりに、期限が切れるまで、サーバ側でファイルを直してもブラウザは気づきません。

### `no-cache`: 確認だけする

`/check.css` は、2 ページ目でもサーバに届いています。ただし、サーバの答えは 200 ではなく 304 です。

304 は「あなたが持っているものから変わっていない」という意味のステータスコードです。本体は送りません。ブラウザは手元のコピーを使います。

この確認のやり取りを **再検証** と呼びます。サーバ側の処理は、次のようになっています。

<!-- source: examples/04-cache.mjs -->
```js
  const etag = `"${req.url.slice(1)}-v1"`;   // ファイルの中身に付けた名札。中身が変わったら変える
  const headers = { 'content-type': 'text/css', 'cache-control': file.control, etag };
  if (req.headers['if-none-match'] === etag) {
    res.writeHead(304, headers).end();        // 「手元のものと同じ」とだけ答える。本体は送らない
    return;
  }
  res.writeHead(200, headers).end(file.body);
```

サーバは 1 回目のレスポンスに、`ETag` というヘッダで名札を付けます。ブラウザは 2 回目のリクエストに、`If-None-Match` というヘッダでその名札を付けて送ります。

名札が同じなら、サーバは 304 とだけ答えます。往復は 1 回かかりますが、本体を運ばないので、大きなファイルほど得になります。

`no-cache` という名前は「保存しない」に見えますが、意味は「保存してよい。ただし、使う前に毎回確認する」です。

### `no-store`: 毎回取り直す

`/never.css` は、2 ページ目でも 200 で本体が返っています。ブラウザはコピーを置かなかったので、もう一度すべてを受け取りました。

「保存しない」は、こちらの `no-store` です。

## 4. 会話についていくための補足

この節の内容は、この本では動かして確かめていません。元のレポートの説明を短くしたものです。

### 「ファイル名にハッシュを付ける」

`max-age` を長くすると速くなりますが、ファイルを直しても気づかれません。この 2 つを両立する定石があります。

ファイルの中身から作った短い文字列（ハッシュ）を、ファイル名に入れます。`app.3f2a1c.js` のような名前です。中身を直すと名前が変わるので、ブラウザから見ると別のファイルになります。

こうしておけば、名前の付いたファイルは 1 年のような長い `max-age` で保存させ、そのファイル名が書いてある HTML だけを `no-cache` にできます。

### 「キャッシュ」は 3 種類ある

職場で「キャッシュ」と言ったとき、指しているものが違うことがあります。

| 呼び方 | 何を保存するか | 誰が出し入れを決めるか |
|---|---|---|
| HTTP キャッシュ | 1 つ 1 つのレスポンス | サーバのヘッダと、ブラウザ |
| Service Worker のキャッシュ（Cache Storage） | 1 つ 1 つのレスポンス | ページの開発者が書いたプログラム。電波がなくても表示する用途に使う |
| bfcache | ページ全体 | ブラウザ。「戻る」「進む」を押したときに、すぐ表示する |

**話がかみ合わないときは、「どのキャッシュの話ですか」と聞くのが早道です。** この章で動かしたのは、1 行目の HTTP キャッシュです。

## 5. 理解度チェック

<!-- quiz: cache-kind -->
**問 1.** `Cache-Control: max-age=600` を付けて配っている CSS を、サーバ側で直しました。5 分前にこの CSS を受け取ったユーザが、別のページへ移りました。そのユーザに、新しい CSS は届きますか。

<details>
<summary>答え</summary>

届きません。600 秒（10 分）の期限内なので、ブラウザはサーバに問い合わせず、手元の古いコピーを使います。

2 節の `/long.css` と同じ動きです。残りの 5 分が過ぎるまで、サーバ側の変更には気づきません。

</details>

<!-- quiz: cache-kind -->
**問 2.** 同僚が「`no-cache` を付けたのに、ブラウザに保存されている。設定が効いていない」と言っています。設定は効いていませんか。

<details>
<summary>答え</summary>

効いています。`no-cache` は「保存してよいが、使う前に毎回サーバに確認する」という指示で、保存を禁じるものではありません。

2 節の `/check.css` は保存されていて、2 ページ目では 304 が返りました。保存させたくないなら `no-store` を使います。

</details>

<!-- quiz: cache-kind -->
**問 3.** 開発者ツールの Network タブで、ある画像の行のステータスコードが 304 でした。この画像について、通信は起きましたか。画像の本体は運ばれましたか。

<details>
<summary>答え</summary>

通信は起きています。本体は運ばれていません。

304 は再検証の結果で、サーバが「変わっていない」とだけ答えたものです。ブラウザは手元のコピーを表示しています。

</details>
