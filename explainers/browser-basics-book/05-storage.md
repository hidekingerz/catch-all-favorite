# 5. 「Cookie に入れる？ localStorage に入れる？」は、何を決めているか

> 所要時間: 読むのに 10 分、手を動かして 3 分
> ゴール: データをどちらに置くと、サーバに送られるか、別の場所から見えるかを判定できる。消えて困るデータの置き場所を判定できる
> 前提: [1 章](01-quickstart.md)（リクエスト、ヘッダ）

## 0. 一枚で

ブラウザには、ページが使うデータを置いておく場所がいくつかあります。会話によく出るのは 2 つです。

| | Cookie | localStorage |
|---|---|---|
| 主に誰が書くか | サーバ（レスポンスのヘッダで渡す） | ページの JavaScript |
| サーバに送られるか | 条件に合うリクエストに、毎回自動で付く | 送られない |
| 見える範囲 | ポート番号が違っても見える | オリジンが同じページだけ |
| 置ける量 | 1 個あたり約 4 KB | 約 5 MiB |
| 向いているもの | ログインの状態 | テーマや言語のような、小さな設定 |

「どっちに入れる？」は、そのデータをサーバにも届けたいか、を決めています。

4 章の保存はブラウザが自動で行うものでした。この章の保存は、サーバやページの開発者が、何を置くかを決めます。

## 1. 2 つの置き場所

**Cookie** は、サーバがブラウザに預ける、名前と値の小さな組です。

サーバは、レスポンスに `Set-Cookie` というヘッダを付けて渡します。ブラウザはそれを保存し、次から同じサーバへ送るリクエストに、`Cookie` というヘッダを付けて送り返します。

サーバには、多くの人のブラウザからリクエストが届きます。サーバは、送り返された Cookie を見て「さっきログインした人だ」と見分けます。

localStorage は、ページの JavaScript が読み書きする保存場所です。名前と値（どちらも文字列）の組を置けます。タブを閉じても残ります。

## 2. 動かして比べる

サーバ A のページで、2 つのデータを置きます。Cookie はサーバが渡し、localStorage はページの JavaScript が書きます。そのあと、サーバ A の別のページを開きます。

```sh
node examples/05-storage.mjs
```

出力の前半は次のとおりです。

<!-- output: storage -->
```
サーバ A のページで、2 つのデータを置いた
  Cookie        session=abc123（サーバ A が Set-Cookie ヘッダで渡した）
  localStorage  theme=dark（ページの JavaScript が書いた）

サーバ A の別のページを開いたとき
  リクエストに付いた Cookie ヘッダ: session=abc123
  リクエストに localStorage の値は: 含まれない
  ページから読んだ localStorage の theme: dark
```

Cookie は、誰も頼んでいないのに、次のリクエストに付いてサーバへ送られました。

localStorage の値は、リクエストには含まれていません。ページの JavaScript が読んだときにだけ、取り出せています。

## 3. オリジン: データの棚を分ける単位

置いたデータを、どのページからでも読めたら困ります。ほかのサイトに、ログインの状態や設定を読まれてしまいます。

そこでブラウザは、URL の先頭の 3 つの部分で、データの棚を分けます。この 3 つの組を **オリジン** と呼びます。

`https://app.example.com:443/settings` という URL なら、オリジンは次の 3 つです。

| 部分 | この URL での値 | 呼び方 |
|---|---|---|
| `https` | 通信の方式 | スキーム |
| `app.example.com` | サーバの名前 | ホスト |
| `443` | サーバの中の窓口の番号。書かなければ、方式ごとの決まった番号になる | ポート |

3 つのうち 1 つでも違えば、別のオリジンです。`/settings` のような後ろの部分は、オリジンに含まれません。

| 比べる URL | `https://app.example.com` と同じオリジンか |
|---|---|
| `https://app.example.com/login` | 同じ（後ろの部分が違うだけ） |
| `https://www.example.com` | 別（ホストが違う） |
| `http://app.example.com` | 別（スキームが違う） |
| `https://app.example.com:8443` | 別（ポートが違う） |

## 4. 演習: ポートだけが違うサーバから見えるか

<!-- exercise: ex-other-port -->

2 節のプログラムは、サーバ B も立てています。サーバ B は、サーバ A とポート番号だけが違います。スキームとホストは同じです。

サーバ A のページでデータを置いたあと、サーバ B のページを開きます。次の 2 つを予想してください。

- サーバ B へのリクエストに、Cookie は付くか
- サーバ B のページから、localStorage の `theme` は読めるか

予想を書いたら、2 節で実行した出力の後半を見ます。

<details>
<summary>答え</summary>

<!-- output: storage -->
```
サーバ B（ポート番号だけが違う）のページを開いたとき
  リクエストに付いた Cookie ヘッダ: session=abc123
  ページから読んだ localStorage の theme: null
```

localStorage は読めません（`null` は「何もない」の意味）。ポートが違うので、3 節のとおり別のオリジンです。サーバ B のページは、サーバ A とは別の棚を見ています。

Cookie は、サーバ B にも送られました。Cookie は歴史的な理由で、ポート番号を区別しません。

この違いが、0 節の表の「見える範囲」の行です。

</details>

## 5. どちらに置くか

この節と次の節の内容は、この本では動かして確かめていません。元のレポートの説明を短くしたものです。

| 置きたいもの | 置き場所 | 理由 |
|---|---|---|
| ログインの状態 | Cookie。`HttpOnly` という指定を付ける | サーバが毎回読む必要がある。`HttpOnly` を付けると、ページの JavaScript からは読めなくなる |
| テーマ、言語のような設定 | localStorage | サーバに毎回送る必要がない。小さく、消えても困らない |
| 大量のデータ、電波がないときにも使うデータ | IndexedDB（ブラウザに内蔵されたデータベース） | localStorage は約 5 MiB までで、文字列しか置けない |

ログインの状態を localStorage に置かないのには、理由があります。localStorage は、ページで動く JavaScript なら何でも読めます。ページに悪意のあるプログラムが紛れ込むと、読み取られます。

逆に、サーバが使わないデータを Cookie に置くのも避けます。2 節で見たとおり、Cookie は毎回のリクエストに付いて送られるので、通信の量が増えます。

## 6. 置いたデータは、消えることがある

ブラウザに置いたデータは、ずっと残るとは限りません。

| 消えるきっかけ | 消えるもの |
|---|---|
| ユーザが、閲覧履歴やサイトのデータを消す | すべて |
| プライベートブラウジングの最後のタブを閉じる | そのあいだに localStorage に置いたもの |
| Cookie の有効期限が来る | その Cookie。期限は長く指定しても、400 日までに切り詰められる |
| 端末の空き容量が足りなくなる | IndexedDB などの大きなデータ。長く使われていないオリジンのものから、オリジンごとまとめて消える |
| 追跡防止が有効な Safari で、あるサイトを 7 日間（Safari を使った日で数える）操作しない | ページの JavaScript が書いたデータ。localStorage も含む。サーバが渡した Cookie は対象外 |

**消えて困るデータの元は、サーバに置きます。** ブラウザに置くのは、消えても取り直せるコピーか、消えても困らない設定だけにします。

「Cookie が消えた」「ログインが外れた」という会話が出たら、この表のどの行にあたるかを確かめます。

## 7. 理解度チェック

<!-- quiz: where-to-store -->
**問 1.** 画面を暗い配色にする設定（`theme=dark`）を、Cookie に置くことにしました。サーバはこの値を使いません。何が起きますか。どこに置くのがよいですか。

<details>
<summary>答え</summary>

サーバが使わない値が、毎回のリクエストに付いて送られます。2 節で、Cookie が次のリクエストに自動で付いたのと同じです。

サーバに届ける必要がないので、localStorage に置きます。

</details>

<!-- quiz: where-to-store -->
**問 2.** `https://shop.example.com` のページが localStorage に書いた値を、`https://blog.example.com` のページから読めますか。

<details>
<summary>答え</summary>

読めません。ホストが違うので、別のオリジンです。

4 節の演習では、ポートが違うだけでも `null` になりました。3 つの部分のどれか 1 つが違えば、別の棚です。

</details>

<!-- quiz: can-vanish -->
**問 3.** メモを書くアプリを作りました。書きかけのメモは localStorage にだけ保存し、サーバには送りません。ユーザが iPhone の Safari で、2 週間ぶりにこのアプリを開きました。メモは残っていますか。どう直しますか。

<details>
<summary>答え</summary>

消えている可能性があります。追跡防止が有効な Safari は、7 日間操作がないサイトについて、ページの JavaScript が書いたデータを消します。localStorage も対象です（6 節の表の最後の行）。

メモはサーバにも保存し、localStorage のものは手元のコピーとして扱います。

</details>
